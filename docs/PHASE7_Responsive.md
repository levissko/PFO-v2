# PFO_NewWeb — PHASE 7：Responsive Design

- 版本：v1.0（2026-09-23）
- 範圍：10 個頁面 × 8 個指定寬度（1920、1440、1280、1024、768、430、390、375）= 80 種組合
- 維護方式（業主定案）：HTML 一律由 `tools/gen_pages.py` 產生；CSS 直接修改 `PFO-v2/assets/css/site.css`
- 審閱模式的測試橫幅依指示保留

## 1. 驗證方法

新增 `tools/rwd_audit.py`（Playwright + Chromium）。每個寬度都用對應的裝置條件載入：寬度 < 1024 啟用觸控模擬，< 768 啟用行動裝置模擬。

每一頁會自動檢查：

| 檢查項目 | 標準 |
|---|---|
| 橫向捲動 | 頁面寬度不得超過視窗寬度 |
| 元素超出視窗 | 除了被 Hero 裁切的裝飾圖形之外，任何元素都不得超出 |
| 文字被裁切 | 元素內容寬度不得超過本身寬度 |
| 觸控目標 | 寬度 < 1024 時，可點擊元素高度 ≥ 44px（段落中的行內文字連結依 WCAG 例外不計） |
| 最小字級 | ≥ 13px |
| 導覽模式 | ≥ 1024 顯示桌機選單；< 1024 改成漢堡選單 |
| 版面資訊 | Header 高度與行數、H1 行數、格線欄數、內容寬度 |

另外在 1920、1280、1024、768、430、375 截全頁圖逐頁目視檢查，並用程式檢查地址和電話是否在數字中間換行。

## 2. 發現的問題與修正

| # | 寬度 | 問題 | 修正 |
|---|---|---|---|
| R1 | 1440、1920 | Header／Footer 使用 1320px 容器，內文用 1200px，Logo 比頁面標題往左偏 60px，左邊界沒對齊 | Header、Footer 的內容寬度改成跟內文一樣的 1200px |
| R2 | 768–1279 | 首頁 Hero 的十字裝飾圖形**壓在副標文字上**（768 最明顯） | 這個寬度範圍內，文字欄最多佔 62%，裝飾圖形縮到 34vw |
| R3 | < 1024 | 麵包屑、404 頁連結、聯絡頁 Email 的點擊區域只有 24–38px 高（共 **68 處**） | 把這些連結的點擊高度撐到 44px |
| R4 | 768 | 3 張據點卡排成 2 欄，第 3 張孤零零一行 | 768–1279 改成單欄橫向卡片（左邊名稱，右邊資料）；≥ 1280 才用 3 欄 |
| R4 | 1024 | 3 欄據點卡太窄，地址被截成「中正路928／號3樓」 | 同上，1024 也用單欄橫向卡片 |
| R5 | 1024–1920 | Footer 三據點欄太窄，地址斷成「2-107號15／樓」「171號／9F-1」 | ≥ 1024 時 Footer 改兩列：第一列放公司資訊與連結，第二列三據點橫排全寬 |
| R6 | 375、768 | 窄螢幕上地址在門牌號中間換行，例如「171號9F-／1」 | `gen_pages.py` 新增 `addr_html()`，讓門牌號碼段（例如「171號9F-1」）不會被拆開；**地址文字本身沒有任何改動**，只在字串外包一層標記 |
